# Postgres with sea-orm

Assumes Rust 1.98 edition 2024, sea-orm 2.0, sea-orm-migration 2.0, Postgres 18, uuid v7 primary
keys, chrono timestamps, cargo-nextest.

Names such as `AppError`, `test_app()`, `Valid<T>` and the Makefile targets come from the rust-scaffolding template. In a project built differently, use its own types, helpers and tooling, map outcomes onto its nearest existing error variant, and say so when none fits instead of adding one. Apply these rules to new code; when editing existing code, keep its public contract and tuned configuration and report differences instead of rewriting, unless asked. If `Cargo.lock` pins another major or minor version than the line above, follow the project and say which rules may not apply.

## Important

- Migration first, always: entities are generated with `--entity-format dense`, never hand-written
  or hand-edited. There is no autogenerate.
- On dense entities, filters use the typed `Entity::COLUMN.field` rather than `Column::Field`;
  `use sea_orm::ExprTrait;`.
- Never `.save()` a new row with an app-assigned key; `.insert()`.
- Service functions take `&C where C: ConnectionTrait` and return `AppError` outcomes by
  classifying `err.sql_err()`; the HTTP status of each variant is `axum-service`'s.

## sea-orm 2.0 is not 1.x

Most sea-orm material predates 2.0, and these renames break nearly all of it:

| 1.x | 2.0 |
|---|---|
| `Expr` methods available on import | `use sea_orm::ExprTrait;` |
| `Expr::col(Alias::new("x"))` | `Expr::col("x")` |
| `DatabaseConnection` enum | struct (the old variants live in `conn.inner`) |
| hand-written `Relation` enum plus `impl Related` | dense format: relations are fields on the model |
| `db.execute(Statement)` | `db.execute_raw(Statement)` |
| `insert_many(..).on_empty_do_nothing()` | gone; an empty iterator is already safe |
| Postgres `serial` primary keys | `GENERATED BY DEFAULT AS IDENTITY` |
| `async fn up(manager: ..)` | `async fn up(&self, manager: ..)` |

`Column::Field.eq(..)` still compiles in 2.0. The typed `Entity::COLUMN.field.eq(..)` is the house
preference, and it exists only on dense entities (`#[sea_orm::model]`): a codebase generated in the
compact or expanded format keeps `Column::X` until someone deliberately migrates it, never as part
of an unrelated change.

## Entities

The dense format carries relations as typed fields on the model, so there is no `Relation` enum to
maintain:

```rust
#[sea_orm::model]
#[derive(Clone, Debug, PartialEq, Eq, DeriveEntityModel, Serialize, Deserialize)]
#[sea_orm(table_name = "user")]
pub struct Model {
    #[sea_orm(primary_key, auto_increment = false)]
    pub id: Uuid,
    #[sea_orm(unique)]
    pub email: String,
    pub name: String,
    pub created_at: DateTimeWithTimeZone, // what the CLI emits for timestamptz
    #[sea_orm(has_many)]
    pub posts: HasMany<super::post::Entity>,
}

impl ActiveModelBehavior for ActiveModel {}
```

`belongs_to` carries the key mapping (`from = "user_id", to = "id"`); `has_many` takes `via =
"post_tag"` for many-to-many. The generator emits `auto_increment = false` for uuid and string
keys. `ActiveModel` holds only column fields, so `..Default::default()` is dead code that trips
clippy. Relation *variants* are named after the target entity, not the field: `posts` produces
`user::Relation::Post`. Tables are singular (`user`, `post`); sea-orm quotes them, so only `psql`
needs `"user"`.

## Migration first, always

There is no autogenerate: no `--autogenerate`, no `diff`, no `--from-entity`. Code generation points
from the database to the entities and never back, so migrations come first:

1. `sea-orm-cli migrate generate add_display_name` is how a migration file is created: it writes
   the timestamped file and registers it in `migration/src/lib.rs`. Rewrite its body in the
   shipped style (`DeriveMigrationName`, the schema helpers); the template's `todo!()` fails
   `-D warnings` until it is.
2. Write `up` and `down` with the schema builder, or raw SQL through `execute_unprepared`.
3. `sea-orm-cli migrate up` (reads `DATABASE_URL`), then `migrate status` to confirm.
4. `sea-orm-cli generate entity --entity-format dense -o src/entities --with-serde both`.
5. Commit the migration and the regenerated entities together.

In a dense codebase `--entity-format dense` is not optional: the generator still defaults to the
1.x compact layout. Index every foreign key column — Postgres indexes the referenced key, never the
referencing one. Sequence anything that removes or narrows as expand, migrate, contract across
releases, since a rolling deploy runs both versions of the code at once.

## Queries

sea-orm is an engine and query builder, not an ActiveRecord framework. Service functions own their
queries directly — there is no repository layer and no per-request session object. Routes and DTOs
are `axum-service`'s.

Filters take the typed `COLUMN` struct, so a type mismatch is a compile error. Optional filters go
into a `Condition`, where `add_option(None)` is a no-op.

```rust
Condition::all()
    .add_option(f.name_contains.as_ref().map(|n| user::COLUMN.name.contains(n)))
    // `eq_any` is `= ANY($1)`, one bind parameter; `is_in` is one per value.
    .add_option((!f.emails.is_empty()).then(|| user::COLUMN.email.eq_any(f.emails.clone())))
```

The typed wrappers do not implement `ColumnTrait`, so four APIs still take the plain `Column` enum:
`.column()`, `.column_as()`, `.cursor_by()` and `.on_conflict_do_nothing_on()`.
`OnConflict::column()` accepts either.

`paginate(db, size)` gives `fetch_page` and `num_items_and_pages`; add a unique tiebreaker to the
sort or OFFSET returns rows twice. `cursor_by` gives keyset pagination. In `raw_sql!`, `{expr}` is
a bind parameter and `{..slice}` expands to a list, so there is no injection surface.

## Relation loading

| Need | Use | SQL |
|---|---|---|
| nested read, one or many parents | `Entity::load().with(post::Entity)` | join for to-one, `IN (..)` batch for to-many |
| parents already fetched, plain models wanted | `parents.load_many(post::Entity, db)` | `WHERE fk IN (..)` |
| one parent and its to-many children | `find_by_id(id).find_with_related(..)` | LEFT JOIN, consolidated |
| a row and its to-one parent | `find_also_related(..)` | LEFT JOIN, flat tuples |
| parents filtered by a child predicate | `has_related(post::Entity, cond)` | `EXISTS` subquery |

`Entity::load().with(..)` is the default: one statement per level whatever the row count.
`find_with_related` cannot be paginated, and paginating `find_also_related` over a to-many is
wrong: `LIMIT` applies to joined rows. A missed load is a value, not an exception: `HasMany` is
`Loaded` or `Unloaded`; nothing shouts, so check `is_unloaded()` yourself. Load every relation
the response touches in the query that fetched the parent.

## Writes

Insert with a struct literal and `.insert()` — it is exhaustive, so the compiler names a forgotten
column:

```rust
user::ActiveModel {
    id: Set(Uuid::now_v7()),
    email: Set(email.to_owned()),
    name: Set(name.to_owned()),
    created_at: Set(chrono::Utc::now().into()), // Utc -> DateTimeWithTimeZone
}
.insert(db)
.await
```

Never `.save()` a new row whose key was assigned in application code. `save()` dispatches on "is the
primary key `Set`", which uuid v7 always makes true, so it issues an `UPDATE` that matches nothing
and fails with `DbErr::RecordNotUpdated`. Update by converting the model back into an `ActiveModel`
and assigning only what changed; untouched columns stay `Unchanged` and never reach the SET clause.

## Transactions

Service functions take the connection generically, so one function works against the pool and
inside a transaction:

```rust
pub async fn create_user<C: ConnectionTrait>(
    db: &C,
    email: &str,
    name: &str,
) -> Result<user::Model, AppError>
```

Add `+ TransactionTrait` only where the function opens its own transaction. Taking
`&DatabaseConnection` instead locks callers out of composing it into a larger unit of work. The
closure form commits on `Ok` and rolls back on `Err`; the explicit form's `commit` and `rollback`
live on `TransactionSession`, which has to be imported.

Work whose effect is a write to this Postgres database takes an advisory lock inside that
transaction (`pg_try_advisory_xact_lock` to run once, `pg_advisory_xact_lock` to serialise);
anything else — an outbound call, a file, work spanning services or outliving
one transaction — takes a Redis lease (`rust-redis`), which only suppresses duplicates, so that
effect must itself be idempotent. The lock goes through `raw_sql!` (`hashtext({key})::bigint`) and
releases with the commit. The blocking form still runs the work on every replica, one after another;
run-once work skips on `false` and inserts a unique `(job, run_date)` row in the same transaction,
so a replica that starts after the leader committed skips too.

Idempotency and the outbox ride on the transaction that does the work. A consumer or a retried
request first inserts its key (the event's `event_id`, or the caller-scoped `Idempotency-Key`)
into a unique column: `on_conflict_do_nothing_on` reporting `Conflicted`, or a 23505, means an
earlier attempt already committed. An event to publish is an `outbox` row in the same
transaction, which a relay publishes (`rust-nats`).

## Errors

`DbErr::sql_err()` is the supported route to a constraint violation: `UniqueConstraintViolation` is
23505, `ForeignKeyConstraintViolation` is 23503. Do not match the inner sqlx error — it sits behind
an `Arc` and its shape is not stable API. Let the constraint reject the row and classify
afterwards; a pre-flight SELECT loses every race. The service maps 23505 to `AppError::Conflict`
with a constant, PII-free string (a 409 is logged at ERROR). For 23503 the parent id's source
decides: from the path (`POST /users/{id}/posts`) the service maps it to
`AppError::NotFound(format!("user {id} not found"))`; from the body it returns the bare `DbErr`,
which reaches `axum-service`'s 422 arm ("invalid reference"). Every status is
`axum-service`'s.

## Testing

Tests run against real Postgres, one database per test: `CREATE DATABASE test_<uuid>`, then
`Migrator::up`, on `TEST_DATABASE_URL` or a reused, named `postgres:18-alpine` container.
`test_app()` (`rust-testing`) does all of this; the nextest process model, the cold-start race and
recovering a wedged container are in `references/testing-db.md`.

## Red Flags — STOP

| About to… | Rule |
|---|---|
| Pass `COLUMN.x` to `.column()`, `.column_as()`, `.cursor_by()` or `.on_conflict_do_nothing_on()` | Those need the `Column` enum; typed columns do not implement `ColumnTrait` |
| Hand-edit a generated entity file | Change the migration, apply it, regenerate |
| Paginate `find_also_related` over a to-many | LIMIT applies to joined rows; paginate parents, then `load_many` |
| Join and filter a child column to select parents | Use `has_related(Entity, cond)`; a join duplicates parents and breaks LIMIT |
| Put `Arc<DatabaseConnection>` in application state | It already wraps an `Arc`; store and clone it by value |
| Write a request extractor that yields a "session" | There is no session-per-request; open a transaction where one is needed |
| Pre-check a parent row before an insert with a foreign key | The check loses the race; insert and let 23503 decide, as Errors says |
| Put an email or a name into a `Conflict` string | 409 is logged at ERROR; PII stays out of the message |
| Create a foreign key with no index on the column | Postgres does not index referencing columns |
| Reach for `MockDatabase` or SQLite to test a query | Neither is Postgres; a per-test Postgres database through `test_app()` (`rust-testing`) |
| Call `find_related` in a loop | N+1 queries; `Entity::load().with(..)`, or `load_many` on the fetched page |
| Run `Migrator::up` at startup across several replicas | Run migrations as a job and gate the startup call |
| Take `pg_advisory_xact_lock` on the pool, or `pg_advisory_lock` with a manual unlock | Take the `_xact_` form on a `DatabaseTransaction`; it releases with the transaction |
| Guard a run-once job with the blocking `pg_advisory_xact_lock` | Every replica waits, then runs it; `pg_try_advisory_xact_lock`, skip on `false` |

## Gotchas

- "No method named X found for struct Select" is a missing trait import: `QueryFilter`,
  `QuerySelect`, `QueryOrder`, `PaginatorTrait`, `EntityLoaderTrait`, `LoaderTrait`.
- sea-orm defaults `sqlx_logging` to on (an INFO event per statement, target `sqlx::query`); the
  scaffold turns it off. Flip it locally, never in production.
